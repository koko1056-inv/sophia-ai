## 5. データベース設計

### 5.1 documents テーブル（ナレッジ）

| カラム | 型 | 説明 |
|--------|-----|------|
| id | bigserial (PK) | 自動採番ID |
| content | text NOT NULL | チャンク化されたテキスト |
| source | text DEFAULT '' | 出典（タイトル/ファイル名） |
| embedding | vector(768) | Gemini Embeddingベクトル |
| created_at | timestamptz | 登録日時 |

### 5.2 faq テーブル

| カラム | 型 | 説明 |
|--------|-----|------|
| id | bigserial (PK) | 自動採番ID |
| question | text NOT NULL | 質問文 |
| answer | text NOT NULL | 回答文 |
| created_at | timestamptz | 登録日時 |

### 5.3 match_documents 関数（RPC）

```sql
match_documents(query_embedding vector(768), match_count int)
→ returns table(id, content, source, similarity)
```

- **検索方式**: コサイン類似度（`<=>` 演算子）
- **計算**: `1 - (embedding <=> query_embedding)` で類似度スコアを算出
- **ソート**: 類似度降順
- **取得件数**: `match_count`（デフォルト: 3）

## 7. RAG 処理フロー

```
ユーザーメッセージ
    │
    ▼
┌──────────────────────────┐
│ 1. ベクトル検索            │
│    query → Gemini Embedding│
│    → Supabase match_documents│
│    → 上位3件のナレッジ取得   │
└──────────┬───────────────┘
           ▼
┌──────────────────────────┐
│ 2. コンテキスト構築        │
│    検索結果をテキスト化      │
│    出典情報を付与           │
└──────────┬───────────────┘
           ▼
┌──────────────────────────┐
│ 3. プロンプト組み立て       │
│    システムプロンプト        │
│    + ナレッジコンテキスト    │
│    + ユーザーメッセージ      │
└──────────┬───────────────┘
           ▼
┌──────────────────────────┐
│ 4. Gemini 応答生成         │
│    model: gemini-2.0-flash │
│    temperature: 0.3        │
│    max_tokens: 1024        │
└──────────┬───────────────┘
           ▼
       応答テキスト
```

### システムプロンプト

```
あなたは株式会社ソフィアのAIアシスタントです。
お客様からのお問い合わせに丁寧かつ正確にお答えします。

ルール：
- 提供されたナレッジ情報に基づいて回答
- 該当情報がない場合は丁重にお断り
- 簡潔かつ分かりやすい丁寧な日本語
- 推測や不確かな情報は提供しない
```

## 10. 設定パラメータ

| パラメータ | デフォルト値 | 説明 |
|-----------|------------|------|
| `gemini_api_key` | (必須) | Google Gemini APIキー |
| `supabase_url` | (必須) | SupabaseプロジェクトURL |
| `supabase_key` | (必須) | Supabase匿名キー |
| `embedding_model` | text-embedding-004 | Embeddingモデル名 |
| `chat_model` | gemini-2.0-flash | チャットモデル名 |
| `chunk_size` | 500 | チャンク分割サイズ（文字数） |
| `chunk_overlap` | 50 | チャンクオーバーラップ（文字数） |
| `top_k` | 3 | ベクトル検索の取得件数 |

## 11. セキュリティ対策

| 対策 | 実装 |
|------|------|
| XSS防止 | `escapeHtml()` でユーザー入力をエスケープ |
| ファイル検証 | `.txt` ファイルのみ許可 |
| APIキー検証 | チャットAPI呼び出し前にキーの存在確認 |
| 環境変数 | `.env` ファイルで機密情報管理（.gitignore対象） |
| 削除確認 | destructive操作前にconfirmダイアログ表示 |

## 12. セットアップ手順

```bash
# 1. Supabase プロジェクト作成後、SQL Editorで実行
#    → supabase_setup.sql の内容を貼り付けて実行

# 2. 環境変数設定
cp .env.example .env
# .env に GEMINI_API_KEY, SUPABASE_URL, SUPABASE_KEY を設定

# 3. 依存パッケージインストール
pip install -r requirements.txt

# 4. サーバー起動
python run.py

# 5. アクセス
# チャット画面: http://localhost:8000
# 管理画面:     http://localhost:8000/admin
```
